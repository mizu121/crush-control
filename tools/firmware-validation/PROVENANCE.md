# Source and implementation record

Date: 2026-10-29. Scope: files newly authored in `tools/firmware-validation`.
License for new code: GPL-2.0-only.

The implementation was authored from the delegated behavioral specification,
the explicitly permitted local generator sources below, official RISC-V and
Unicorn documentation, and data from the user's exact OEM file. It was not
ported from an earlier validation implementation. This is a factual development
record, not a legal opinion or a claim to independent invention of the protocol,
instruction set, constants, or licensed patch routines.

## External references actually consulted

- [RISC-V RV32I specification, v20260120](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html): register model and base ISA context. Standard execution is delegated to Unicorn; no copied ISA interpreter is supplied.
- [Unicorn 2.1.4 official RISC-V Python example](https://github.com/unicorn-engine/unicorn/blob/2.1.4/bindings/python/tests/test_riscv.py): RV32 initialization and callback API usage. The harness architecture and checks were authored separately.
- [Unicorn official C API](https://github.com/unicorn-engine/unicorn/blob/master/include/unicorn/unicorn.h): instruction/memory hook and stop contracts.
- Installed Unicorn 2.1.4 Python API documentation/source for `ctl_exits_enabled` and `ctl_set_exits`: stops before translation of unsupported instructions at a boundary. No Unicorn source is vendored.
- [Unicorn 2.1.4 COPYING](https://github.com/unicorn-engine/unicorn/blob/2.1.4/COPYING): GPL version 2 license text; copied verbatim into `COPYING` as the harness license.
- [Capstone 5.0.7 license](https://github.com/capstone-engine/capstone/blob/5.0.7/LICENSE.TXT): BSD 3-clause dependency license.

Unicorn 2.1.4 and Capstone 5.0.7 were installed in a separate ignored local venv.
Their code/binaries are not part of the authored source package. Capstone is
used only to inspect the live user-supplied stock epilogue. No Andes semantics
were implemented; unsupported execution fails closed. Search results for
Andes documentation were inspected during scoping but no Andes document/code
was used to author an emulator extension.

## Evidence boundaries

`validation.py` defines expectations from the requested behavior, then runs the
generated bytes and observes state. It does not fabricate protocol responses,
RGB results, OEM helper return values or USB completion. The capability mutation
test demonstrates a changed instruction stream changes the result. Exact OEM
execution and generated-routine execution have separate scope labels in JSON.
Missing OEM input is visible as `NOT_REQUESTED` and is never counted as a passed
OEM check. These tests do not recover or certify any retired suite's coverage.
